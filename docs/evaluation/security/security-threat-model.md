## Scope, assets and actors

The system is a Next.js application on Vercel, backed by Neon PostgreSQL/pgvector, private Vercel Blob, Upstash QStash and server-side AI generation through Vercel AI Gateway. The issue's older reference to direct Gemini calls is superseded by the checked-in gateway design: the gateway and the selected downstream model provider are both external data recipients. Browser sessions use Google-only Better Auth. A daily cleanup endpoint is planned; no checked-in cron route currently exists. Decks, reports, notifications and account deletion remain planned. Materials, topics, quiz generation, attempts, progress and revision now have code, although #19 was written before they existed.

| Asset | Security need | Where it crosses trust boundaries |
| --- | --- | --- |
| Student uploads, extracted text, chunks, topics and vectors | Private to owner; selected sources stay in one space; reliable retirement/deletion | Browser → app/Blob → worker/database → gateway/model |
| Quiz answer keys, explanations, model answers and citations | Hidden until the relevant reveal/submission contract; correct source membership | Database → API → browser; generator → database |
| Attempts, scores, mastery and revision schedules | Owner-only; server-authoritative; duplicate submissions cannot change evidence | Browser → API → database |
| Session cookies, OAuth state/PKCE and Google tokens | No impersonation; revocable sessions; token confidentiality | Browser/Google → Better Auth → database |
| Database, Blob, queue, gateway, auth and cron credentials | Server-only secrets; scoped per environment; never in responses/logs/fixtures | Local environment/Vercel → service adapters |
| Job claims, generation slots, queue messages and cleanup intent | Authenticated, bounded and idempotent processing; survival across crashes | QStash → worker → database/Blob/gateway |
| Security evidence and provider metadata | Accurate, anonymised; no hidden prompt/source/token copies | Developer/test environment → public repository |

Actors include a signed-out visitor, a malicious signed-in student, an uploader embedding instructions or malformed parser inputs, a sender forging/replaying worker requests, and an accidental operator misconfiguration. Google, hosting, storage, queue and model services are trusted only for their defined functions; provider compromise, account misuse and policy changes remain external risks. Student IDs, role claims, file names/MIME/size, source text, AI output, query parameters and resource IDs from a browser are untrusted. A valid signature authenticates a queue message, not permission to bypass current resource state or ownership consistency.

## Assumptions, deviations and next review

The public repository is treated as readable by anyone. Host/service credentials and Google configuration are supplied privately; free-tier service availability is not a confidentiality guarantee. Provider data retention/training terms, store privacy, HTTPS cookies, database isolation and Preview callback reachability need account-level confirmation. Source review does not establish those facts.

Current material deletion explicitly follows the newer T-06b Blob-first contract in Section 4. The same PRD still describes independent durable cleanup for space/account deletion and crash recovery; do not silently treat those designs as already implemented. The source model's 17-table description is a target design, not proof every proposed table exists; inspect migrations for the task being tested.

Revisit this model whenever a new API/worker, provider, file parser, deletion path or reveal contract lands. Re-run the route-matrix coverage review for that commit. No residual risk here is accepted on behalf of the team: owners must record acceptance or remediation, with reviewer and date, in the risk register.
